herdr-session-hub plan
Project plan · v0.1 draft

herdr-session-hub

Owner: David11 Oct 2026Target herdr: 0.9.xGo · single binarymacOS (MacBook)Apache-2.0github.com/davidsugianto/herdr-session-hub

A small companion server that sits next to all your herdr sessions (work and personal labs) and lets you watch and steer your agents from your iPhone or a terminal. It sees which agents are working, waiting, blocked or finished, keeps a live timeline, pings you the moment one needs you, and lets you approve, reply or interrupt without walking back to your desk.

01

Goals and boundaries

In scope

  • Live board of every agent across all herdr sessions and workspaces, grouped by state, filterable by session
  • Simple timeline: a state strip per agent plus an event feed
  • Read output; approve, trust tool, deny, reply, send text, send keys, interrupt
  • Instant notifications for blocked and finished agents, with deep links
  • Two surfaces: mobile web app (PWA) and terminal UI
  • Works on localhost with zero config; remote over Tailscale with one command

Out of scope (v1)

  • A full terminal emulator in the browser. Output is read as text, not a live PTY
  • Starting new agents or editing layouts (herdr already does this well)
  • Multi-user accounts and roles. One owner, one token
  • Hosted relay or cloud service. Everything runs on your machine
  • Public internet exposure. No Tailscale Funnel, no Cloudflare tunnel
  • Changes to herdr itself. We only use its public socket API
  • Discord bot and daily digest. Planned for later (section 14)
Reference: herdr-demo.pages.dev (herdr-remote). We keep what works there: relay URL plus token pairing, a touch key grid (Esc, Tab, arrows, Enter), one-tap quick replies (yes, no, continue, retry), and push for blocked agents. We change the shape: it opens on settings, we open on the agent board, and we add per-agent status, a timeline and a TUI.
02

How it talks to herdr

herdr exposes a local socket that speaks newline-delimited JSON (Unix domain socket on Linux and macOS, named pipe on Windows). The default path is ~/.config/herdr/herdr.sock, and named sessions live under ~/.config/herdr/sessions/<name>/herdr.sock. The hub keeps one long-lived client per session socket it finds. No herdr patches, no screen scraping of our own.

Startup follows the order herdr documents for cache clients: open the event subscription first, wait for it to start, then call session.snapshot on a second connection and treat later events as signals to re-read. If the server sends events_lost, the hub resubscribes and reconciles from a fresh snapshot instead of trusting its cache.

herdr integration install omp

Multiple sessions

You run separate herdr sessions for work and personal labs, so session is a first-class part of the model, not an afterthought.

  • Discovery. On start the hub connects to the default socket and every ~/.config/herdr/sessions/*/herdr.sock, and watches that folder, so a session started later with herdr --session labs appears on the board within a second.
  • Isolation. Each session has its own subscribe, snapshot and reconnect loop. If the labs server stops, its agents show as offline and work keeps updating.
  • One board, one app, one notification stream. Every agent carries a session tag and color. The iPhone app and TUI show all sessions by default, with a session filter.
  • Per-session rules. Mute or set quiet hours per session, e.g. silence work on weekends while labs still notifies.
# ~/.config/herdr-session-hub/config.toml  (all optional)
[discovery]
auto = true                  # default socket + sessions/*

[[session]]
name  = "work"               # matches herdr --session work
color = "blue"
quiet_hours = "Sat-Sun"      # blocked still notifies unless muted

[[session]]
name  = "labs"
color = "green"

[mac]
keep_awake = "while-working" # off | while-working | always
03

State model

herdr reports idle, working, blocked, done and unknown, where done means idle and not yet seen. The hub maps those into the four words you asked for and adds one rule: once you open a finished agent anywhere (phone or TUI), it becomes waiting.

Hub stateFrom herdrMeaningNotify?
blockedblockedNeeds a permission answer or input to continueYes, immediately, high priority
finisheddoneTurn ended, you have not looked yetYes, immediately
workingworkingBusyNo
waitingidle, or done after you viewed itReady for the next promptNo
unknownunknownPlain shell or undetected agentNo, hidden by default
  • Stable identity. Pane ids like w1:p2 change when a pane moves across workspaces, so the hub keys agents by session/terminal_id (for example labs/term_abc123) and keeps the pane id only as an address. Two sessions can both have a w1:p1; the session prefix keeps them apart.
  • Timeline storage. Every state transition is a row in SQLite (session, agent, from, to, at, source). The strip view and the daily digest are both queries over that table. 14 days kept by default.
  • Flap guard. A blocked to working to blocked bounce inside 3 seconds counts as one blocked episode, so one prompt gives one notification.

Architecture

One Go binary, hub, with subcommands. The server holds the only herdr connections (one per session); every surface is a client of the hub API, which keeps behavior identical across phone and terminal. Notifications go through a small sink interface (Web Push in v1), so a Discord bot can be added later as one more sink and one more API client, with no changes to the core.

Output viewer

Pulls the last 300 lines with pane.read --source recent-unwrapped, strips control sequences server side, keeps basic ANSI colors, and refreshes on pane.updated or every 2 s while open. Follow-tail by default; scrolling up pauses it. Find-in-output and a copy button.

Reply sheet

Composer with quick replies taken from the reference app (yes, no, continue, retry, commit and push) plus your own presets. Sends through agent.prompt; if the agent is blocked it switches to the approval buttons instead of typing into the prompt.

Keys tab

The reference key grid: Esc, Tab, Shift+Tab, arrows, Enter, Ctrl+C, PgUp, PgDn, plus a 1 to 9 row for numbered menus. Targets the agent you last opened.

Feel

System font stack in the app for speed, state colors carry meaning everywhere, large tap targets (44 px), haptic tick on actions where supported, offline banner when SSE drops, light and dark following the system.

06

Actions

herdr is agent-agnostic, so approve and trust differ per agent. The hub ships small agent profiles (TOML) that describe how to read a prompt and which keys answer it. A profile that cannot parse the current screen falls back to the raw key grid, so nothing is ever unanswerable from the phone.

Stale-prompt protection: every approval card carries a short hash of the parsed prompt. If the screen changed between the notification and your tap, the hub rejects the action and shows the new prompt instead of pressing 1 on something else.

Every action goes into an audit table (who, surface, agent, action, payload, result) and shows up in the timeline feed. Profiles for v1: Claude Code, pi, omp, plus a generic fallback. For pi the main value is finished alerts and quick replies rather than approvals. Exact prompt strings and keys for all three get verified against real sessions in the spike, since they change between agent versions.

07

Notifications

Two events notify: an agent becomes blocked, or an agent finishes. Both fire as soon as the herdr event arrives (target under 1 s from herdr to phone on Web Push). Nothing else notifies unless you add a rule.

On your iPhone

ChannelOpen outputApproveType a reply
Web Push to the Home Screen appTap opens agent detail, scrolled to the endNo buttons inside iOS web notifications; tap, then one tap on Approve (already under your thumb)Tap opens the reply sheet with the keyboard up
Honest limit: iOS does not let a web app put buttons or a text field inside its notification. The plan makes tap-to-action as short as possible instead: notification, tap, Approve. Two taps, no typing, no hunting for the agent.

iPhone setup, once

  1. Install Tailscale on the iPhone and sign in to the same tailnet as your computer. Run hub tunnel on the computer.
  2. Scan the QR with the Camera, which opens the hub in Safari and pairs the device.
  3. Share, then Add to Home Screen. Web Push only works for Home Screen web apps (iOS 16.4 or later).
  4. Open it from the Home Screen and tap Enable notifications. iOS only asks after a tap, so the app shows this button on first launch.
  • Web Push needs HTTPS, and the hub runs on your computer, so the iPhone always connects through Tailscale, even at your desk. Keep the Tailscale VPN on for the phone to reach the app; push notifications themselves arrive through Apple either way.
  • iOS suspends the app in the background, so the live stream stops. Push is what reaches you; when you open the app it reloads state from a fresh snapshot.
  • The Home Screen icon shows a badge with the number of agents that need you (blocked plus finished and unread).
  • If the app is open in front of you, it shows an in-app banner instead of a system notification.
  • Quiet hours with a "blocked still notifies" switch. Mute per agent or per session.
  • Notification title starts with the session, e.g. [labs] claude · upsera is blocked, then the parsed question or the last output line, and a deep link to /a/<session>/<terminal_id>.

Local and remote access

At your desk

Zero setup

hub serve finds every herdr session socket, binds 127.0.0.1:7878, and generates a token and VAPID keys on first run. Open it in a browser on the same machine, or run hub tui.

iPhone, anywhere

Tailscale, one command

hub tunnel runs tailscale serve in the background for port 7878, which gives a private HTTPS URL like https://macbook.<tailnet>.ts.net with a real certificate. Only devices on your tailnet can reach it. It prints a pairing QR. hub tunnel off removes the serve config.

On the MacBook

  • Sleep is the big one. When the Mac sleeps, herdr, your agents and the hub all pause, and the iPhone app shows "MacBook offline since 23:40". By default the hub holds a macOS power assertion (the same mechanism as caffeinate -i) only while at least one agent is working, so the Mac does not idle-sleep mid-task and can sleep normally once everything is done.
  • Closing the lid on battery still sleeps the Mac; no app can stop that. Keep it open, or on power with an external display in clamshell mode, when you plan to steer agents from your phone.
  • Starts at login. hub service install writes a LaunchAgent in ~/Library/LaunchAgents, so the hub starts at login and restarts if it crashes. The herdr plugin autostart remains as an alternative.
  • Tailscale app. hub tunnel uses the tailscale CLI from your PATH (Homebrew) or, if missing, the one inside the Tailscale app bundle, so it works with either install.

Security

  • Sending text to an agent can run arbitrary commands on your machine, so the hub treats its token like an SSH key.
  • Pairing uses a one-time code in the QR that exchanges for a long-lived token stored in an HttpOnly, Secure cookie. Revoke devices from Settings or hub devices revoke.
  • Tailscale identity as a second check. tailscale serve adds a Tailscale-User-Login header to each request and strips any spoofed copy. The hub only accepts remote requests whose login matches yours, on top of the device token.
  • Tailscale Funnel is never used, so the hub is never on the public internet. Prerequisite: HTTPS certificates enabled for your tailnet (the Tailscale CLI asks the first time).
  • Optional read-only token for sharing a view without action rights.
  • Rate limit on action endpoints, CSRF check on POST, strict CSP, no listening on 0.0.0.0 unless you pass --listen.

LicenceApache-2.0

Why Apache-2.0. It is permissive like MIT, so anyone can use, fork and embed the hub, and it adds an explicit patent grant and a clear contribution clause. It is also the licence most of the ecosystem you work in uses (Kubernetes, Prometheus, OpenTelemetry), which makes outside contributions easy. herdr itself is AGPL-3.0, but the hub contains none of herdr's code and only talks to it over its socket and CLI, so the two licences do not mix. Not legal advice; this is the common reading for separate programs that talk over an API.

All decisions made. The plan is ready to build, starting with milestone 0 in davidsugianto/herdr-session-hub.

Attention message

When an agent blocks, the bot posts the agent, the parsed question and the last few lines, with buttons: Approve, Trust, Reply (modal), Read output, Interrupt. After you act, the message edits itself to show who answered and from where.

Daily digest

Per agent: time working, number of blocked episodes and median time to unblock, turns finished, last output line. Totals for the day, the longest wait you caused, and anything still blocked or finished but unread.
